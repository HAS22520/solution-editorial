# 思路怎么写

题解的差异不在代码，在思路段。代码人人写得出，思路段决定读者是"抄了个答案"还是"学会了"。

## 一、先符号化，再动笔

动笔前把题目压成一张小表：

| 符号 | 含义 | 约束 |
|---|---|---|
| n | 序列长度 | ≤ 2×10^5 |
| a_i | 第 i 个元素 | \|a_i\| ≤ 10^4 |
| k | 窗口长度 | ≤ n |

这张表的作用：后面所有段落、所有代码都用同一套符号。符号一旦统一，边界条件会自己浮出来（比如 `k > n` 时表里就矛盾了）。

## 二、思路四段式

### 1. 观察（找结构）

问自己四个问题，任何一个有肯定答案就有戏：

- 有没有**单调性**？（能不能二分，能不能用单调队列/栈）
- 有没有**可合并性**？（能不能分治、能不能用前缀和做差）
- 有没有**等价变形**？（补集、翻转、排序后相邻、离散化）
- 有没有**小的状态**？（能不能把决策压成常数个状态，从而 DP）

### 2. 转化（换问题）

一个说法：**把"求什么"换成"维护什么"**。

- 求子段和最大值 → 维护"以 i 结尾的最优值"（Kadane）。
- 求区间第 k 小 → 维护"值域上的计数"（主席树/树状数组二分）。
- 求最短覆盖 → 维护"右端点固定时最优左端点"（双指针）。

转化讲清了，代码基本就定型了。

### 3. 算法（数据结构 + 不变量）

必须同时写清两件事：

- **不变量**：循环每轮开始时什么恒成立。
- **为什么维护它**：这个不变量如何保证答案被取到。

反面例子（只有步骤）：

> 用单调队列保存下标，每次入队前弹出队尾，队首过期就弹出，输出队首。

正面例子（有理由）：

> 维护下标队列，使 `a[q[head..tail]]` 严格递减。新元素入队时弹出队尾所有不大于它的下标——它们已被当前元素支配：只要当前元素还在窗口内，它们不可能成为最大值。于是队首永远是当前窗口最大值。

### 4. 正确性与复杂度

正确性四条路，选一条走通即可：

| 论证方式 | 适用 | 写法 |
|---|---|---|
| 不变量 | 双指针、单调结构、并查集 | "循环每轮开始前 P 成立；每次操作保持 P；结束时 P 蕴含答案正确" |
| 归纳 | 递归、DP、分治 | "基础情形显然；假设规模 < n 时成立，证规模 n 时成立" |
| 反证 | 贪心、最优性 | "假设存在更优解，则与选择规则矛盾" |
| 交换论证 | 排序贪心、调度 | "把最优解中相邻两项交换后不变差，故可整理成算法的选择顺序" |

复杂度两句话：

> 时间 O(n)：每个下标入队、出队各一次。空间 O(n)：队列与数组。

不写"时间复杂度为 O(n)，空间复杂度为 O(n)，效率较高"这种凑字数的尾巴。

## 三、按难度调整篇幅

| 难度 | 思路段 | 重点 |
|---|---|---|
| 入门（模拟、枚举） | 5~10 行 | 说清枚举什么、边界是什么，别硬凑正确性 |
| 中等（DP、双指针、二分） | 15~25 行 | 状态定义 + 转移 + 不变量 |
| 较难（数据结构组合、图论建模） | 25~40 行 | 建模过程 + 为什么这个结构能降复杂度 |

## 四、一个自检问句

写完思路，问自己：

> 一个只看这段文字、不看代码的人，能不能照着它把这题重写出来？

不能，就说明转化或不变量的某一句还空着。
